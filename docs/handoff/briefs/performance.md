# Brief: Make seanfinch.com faster on laptop and mobile (overnight, local only)

- **Model:** any capable coding model (written so it runs unattended)
- **Access:** read-write, **local only**
- **Branch:** create local branch `perf/overnight` from `dev`. Never push it.

## Goal

Sean wants the site to load and feel noticeably faster on a laptop **and on a phone**,
with **no loss of visual quality or charm**: same design, same photos at the same visual
sharpness, same animations for people who haven't asked for reduced motion. He is
asleep while you work. Make every decision yourself, never wait for input, and leave
him a near-finished result plus a short report of what's left to tweak.

## Hard rules (read twice)

- **Never push, and never publish anything.** No `git push`, no `gh` commands that
  write (no PRs, comments, merges, releases), no Netlify or GitHub API calls that
  change anything, no deploys. Everything is tested locally. Local commits on
  `perf/overnight` are fine and encouraged (small, one change each).
- Never `--no-verify`, never `git reset --hard`, `git checkout -- <file>`, `git stash`
  or `git clean` on work you didn't create in this session. Don't switch away from
  `perf/overnight` once you've started.
- Commits follow `CONTRIBUTING.md`: subject ≤72 chars, no trailing period, body of
  `- ` bullets (≤8). **No AI attribution of any kind**: no co-author trailers, no
  "generated with" lines. The hooks will reject them.
- Never modify, re-encode or rename anything in `public/photography/` (originals are
  cached immutably for a year; see `CLAUDE.md`). Derivatives in `_derived/` are
  generated by `vite.config.ts` and are fine to change through that plugin.
- New versions of other public files get **new filenames** (`pfp-256.webp`), never an
  overwrite of a name that's already deployed. Files under `src/assets/` are
  content-hashed by Vite, so replacing those in place is fine.
- Don't add runtime dependencies. A dev-only tool is OK only if it clearly pays off;
  note why in the report. `lucide-react`/`sonner` are local stubs; never install them.
- No visual redesign. If a change would visibly alter the page (layout, crop, color,
  animation), don't make it; list it in the report as an option instead.
- `git push`, `gh` and `netlify` are denied in `.claude/settings.local.json` for this run.
  Never edit or commit that file (or `.claude/settings.json`); stage files by path,
  never `git add -A` or `git add .`.
- If something blocks you (a tool won't run, a permission prompt), skip that item,
  write down exactly what happened, and continue with the next one.

## Steps

1. **Baseline.** `git switch -c perf/overnight dev`, commit the handoff docs, then
   `npm run build` and `npx vite preview --host 127.0.0.1 --port 4173 --strictPort` in
   the background. For each of `/`, `/about`, `/projects`, `/experience`,
   `/photography`, run Lighthouse **3 times for mobile and 3 for desktop** and keep
   the median. Write results outside the repo, in
   `%TEMP%\seanfinch-perf\before\`:
   ```bash
   EDGE="C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"
   npx -y lighthouse@13 http://127.0.0.1:4173/about --chrome-path="$EDGE" \
     --chrome-flags="--headless=new" --only-categories=performance \
     --output=json --output-path="$TEMP/seanfinch-perf/before/about-mobile-1.json" --quiet
   # desktop: add --preset=desktop
   ```
   Record performance score, LCP, TBT, CLS, total transfer bytes per page.
   Also take **before screenshots** (desktop 1440 wide, mobile 390 wide) of each page
   with headless Edge against the preview server. Use a fresh `--user-data-dir` per
   shot or Edge writes nothing:
   ```bash
   "$EDGE" --headless=new --disable-gpu --hide-scrollbars --no-first-run \
     --user-data-dir="$TEMP/seanfinch-perf/prof-$RANDOM" --window-size=1440,2600 \
     --timeout=6000 --screenshot="$TEMP/seanfinch-perf/before/about-desk.png" http://127.0.0.1:4173/about
   ```
   (The dev server renders blank headless; always use `vite preview`.)
2. **Right-size the three oversized images** (largest, safest win).
   - Write `scripts/optimize-images.mjs` (sharp, already a devDependency) that writes
     new files and never overwrites existing ones: `public/pfp-{160,320,640}.webp`
     and `public/SeanPortrait-{480,960,1440}.webp` (quality ~80, metadata stripped).
     Use sizes that cover 2× the largest rendered size.
   - Re-encode `src/assets/audax-group.jpeg` in place (same 200×200, strip metadata).
   - Switch `Home.tsx` / `About.tsx` to `<img srcSet sizes width height>` with the new
     files; keep the old files in `public/` (they may be linked externally). Add
     `width`/`height` to prevent layout shift, `decoding="async"`, and
     `loading="lazy"` only for images below the fold.
3. **Route-level code splitting (backlog SF-9).** In `src/App.tsx`, keep `Home` eager
   and `React.lazy()` every other page (Photography, About, Projects, Experience,
   Contact, cipher tools, homelab/diagram pages, NotFound), wrapped in one `<Suspense>`
   whose fallback is an empty `min-h-screen` block (no spinner flash, no layout jump).
   Keep the `photos` preload in `App.tsx` working. Confirm the main chunk shrinks and
   that `react-zoom-pan-pinch` lands only in the Photography chunk.
4. **Responsive photography images.**
   - Add a `medium` derivative (1200 px, quality 78) to `DERIVATIVES` in
     `vite.config.ts`, export `photoMedium()` from the manifest, add it to the
     `virtual:photo-manifest` types in `src/vite-env.d.ts`, re-export it in
     `src/data/photos.ts`, and **bump `DERIVED_VERSION`**. Keep the attribution
     EXIF/XMP exactly as is.
   - Hero and lightbox images use `srcSet` (`medium 1200w, large 2000w`) with
     appropriate `sizes`; tiles keep the 500 px thumb. "Full quality" still loads the
     original. Verify a derivative still carries Artist/Copyright with `exiftool`.
5. **Fonts.** Find where `@fontsource` is imported (`src/main.tsx` / `src/index.css`)
   and import only the Latin subset and only the weights actually used (grep for
   `font-` weight classes per family). Keep `font-display: swap`. Don't change which
   families are used. Optionally preload the one Latin woff2 that renders the hero
   heading if Lighthouse shows it on the critical path.
6. **Be gentler on phones.** In `src/App.tsx`, skip the 3 s thumbnail preload when
   `navigator.connection?.saveData` is true or the effective type is `2g`/`3g`, and
   run it in `requestIdleCallback` where available. Same guard for the Navbar hover
   preload (hover rarely fires on touch anyway).
7. **`prefers-reduced-motion` (backlog SF-10).** In `src/index.css`, under
   `@media (prefers-reduced-motion: reduce)`, disable `.scroll-reveal` transitions
   (show content immediately), `animate-pulse-dot`, and hover scale transforms. No
   change for everyone else.
8. **Anything else Lighthouse flags** that fits the rules: unused CSS, render-blocking
   resources, missing image dimensions, large DOM. Leave the CSP and headers in
   `netlify.toml` alone unless a change is required and `npm run security:headers`
   still passes.
9. **After.** Rebuild, re-run the same Lighthouse matrix into `after\` and the same
   screenshots. Compare every screenshot pair by eye (open both). Any visible
   difference beyond identical rendering is a regression: fix it or revert that change.

After **every** step: `npm run check`, `node scripts/check-content.mjs tree`,
`git diff --check`, then a local commit. If a step makes things worse in Lighthouse,
revert that commit with `git revert` (not reset) and note it.
